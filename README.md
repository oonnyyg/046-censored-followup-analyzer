# censored-followup-analyzer

将本地随访记录整理为可复核的生存分析报告。仅使用 Python 3.12 标准库，
按 Kaplan–Meier 口径区分**实际事件**与**右删失**，不做医学判断或额外推断。

## 调用方法

```bash
python -m followup_survival \
  --records examples/records.csv \
  --config examples/config.json \
  --output-dir examples/output
```

任一输入不合法时程序以非零状态退出，错误信息定位到具体 CSV 行或配置项，
且不会覆盖输出目录中已有的旧报告。

## 输入：记录 CSV

每个对象**只有一条记录**，从第 0 天开始观察。默认列名如下，均可在配置中改名：

| 列 | 含义 | 要求 |
| --- | --- | --- |
| `id` | 对象编号 | 非空、全表唯一 |
| `group` | 分组名称 | 非空；`__overall__` 为保留名，禁止使用 |
| `days` | 随访天数 | 非负整数 |
| `event` | 结束标记 | `1` = 当天发生事件，`0` = 当天右删失；其他值拒绝 |

空数据表（无表头或无数据行）、重复编号、缺失/空白字段、非法天数或事件标记
都会导致校验失败。允许出现未使用的额外列。

## 输入：配置 JSON

```json
{
  "query_days": [0, 2, 3, 6, 9, 12]
}
```

- `query_days`（必填）：非空数组，元素为非负整数；去重后按升序处理。
- 可选列名覆盖：`id_column`、`group_column`、`days_column`、`event_column`，
  均为非空字符串且互不相同。

## 统计口径

1. 分别计算**总体**以及数据中**实际存在的每个分组**，分组按名称排序。
2. 先按观测天数聚合。某天的在险数 = 随访天数大于等于该天的对象数。
3. 同一天既有事件又有删失时：先用当天全部在险对象计算事件对概率的影响，
   再一并移除当天的事件与删失对象，结果与输入行顺序无关。
4. Kaplan–Meier 生存概率初值为 1；每个事件日乘以
   `1 - 当天事件数 / 当天在险数`；只有删失的日子概率不下降。
5. 概率在随访范围内一旦降到 0，之后保持 0。
6. 查询天数口径：
   - 首次观测日之前：概率为 1；
   - 两次观测日之间：沿用最近一个观测日处理后的概率；
   - 查询恰逢事件日：采用当天下降**之后**的概率；
   - 超过该总体/分组的最大观测日：概率为 `null`（CSV 中留空）并标记
     `out_of_followup=true`，不外推，但仍报告该查询日的在险数
     （按 `days >= 查询日` 计数）。
7. 中位生存天数 = 生存概率**首次小于等于 0.5** 的事件日；随访期内未达到
   时为 `null`，并在汇总中说明原因。

## 输出文件（写入 `--output-dir`）

- `step_details.csv`：总体与各组每个不同观测日的阶梯明细
  （处理前在险数、事件数、删失数、处理后概率）。
- `timepoint_report.csv`：每个总体/分组在各查询天数的在险数、概率
  及是否超出随访范围。
- `summary.json`：总体与各组的对象数、事件数、删失数、中位生存天数及说明，
  以及去重排序后的查询天数。
